# 本地滑块自动识别测试

这是一个完全本地的合成滑块页面，不连接 WebVPN 或任何真实认证系统。当前版本使用右侧凸耳、底部凹口的不规则拼图槽位，背景为程序生成的庭院照片式场景，并加入噪声、局部遮挡和随机显示缩放。

## 运行

```powershell
# 启动可交互页面，手动观察
node test\slider-demo\server.mjs

# 自动识别并拖动，跑 5 轮
node test\slider-demo\solve.mjs --rounds 5

# 显示浏览器窗口
node test\slider-demo\solve.mjs --headed --rounds 3

# 保存首轮拖动前截图
node test\slider-demo\solve.mjs --rounds 3 --screenshot

# 使用固定轨迹种子
node test\slider-demo\solve.mjs --rounds 5 --seed 20261018

# 切回旧版线性拖动作为基线
node test\slider-demo\solve.mjs --rounds 3 --motion linear
```

## 流程

1. `puzzle.html` 在 480×240 的内部 Canvas 上随机绘制带纹理的背景。
2. 从背景中复制一块 72×72 的不规则拼图纹理，拼图块和目标孔使用同一条 Canvas 路径。
3. 目标孔叠加半透明压暗、双色边框、噪声和局部遮挡。
4. 每轮随机改变显示宽度（300–360px），坐标不写入 DOM、URL 或全局状态。
5. `solve.mjs` 对场景和拼图块做灰度化、3×3 模糊和 Sobel 边缘检测。
6. 使用模板边缘点在场景边缘图中做归一化粗搜索，再在峰值附近逐像素精搜。
7. 使用 Canvas、方块和轨道的 `boundingBox()` 换算页面坐标，处理内部像素与 CSS 显示缩放。
8. 用 `page.mouse` 模拟按住、移动、松开，页面在容差内判定成功。
9. `--rounds` 每轮点击“换一题”，验证识别流程不是只对固定坐标有效。

## 拖动轨迹

默认 `--motion natural`，拖动过程包含：

- 按下前 70–190ms 的接近停顿
- 按下后 35–115ms 的起手停顿
- 随距离变化的加速、减速，目标时长约 0.52–1.05 秒
- 18–32ms 的随机事件间隔
- ±3px 的起手位置偏移和轻微纵向漂移
- 2–6px 的末端过冲，再回正到精确目标
- 松手前 55–145ms 的停顿

一次 20 轮自然轨迹实测：

```text
成功率:     20/20
实际步数:   27 - 38
实际耗时:   714 - 1073ms
末端过冲:   2.1 - 5.7px
最终位置:   全部进入页面容差
```

`--seed` 只固定轨迹随机数，页面每轮的纹理和缺口仍会重新随机生成。`--motion linear`
保留旧的 30 步直线拖动，用于比较两种输入方式的差异。

## 可扩展方向

- 增加旋转、透视或更强的遮挡，评估模板匹配的鲁棒性。
- 使用 `page.screenshot()` 和图像处理库做外部识别，而不是在 Canvas 内读取。
- 通过 `page.on('response')`、截图和 trace 记录失败上下文。
- 将识别结果与页面闭包中的期望坐标对比，统计误差和成功率。

## 匹配算法

- 灰度化：`0.299R + 0.587G + 0.114B`
- 降噪：3×3 均值模糊
- 边缘检测：Sobel 梯度，阈值 36
- 模板：从拼图块边缘图中抽样最多 650 个点
- 粗搜索：场景边缘图上每 2px 搜索一次，使用边缘交并比评分
- 精搜索：在粗搜索峰值附近 ±4px 内逐像素搜索
- 最低绝对分数：0.12
- 第二候选间隔：至少 0.008，且第二候选必须与第一候选相距 24px 以上

一次 20 轮实测结果：

```text
成功率:     20/20
显示缩放:   0.629 - 0.746
噪声比例:   0.31% - 0.98%
遮挡半径:   10.0 - 17.0px
模板边缘:   2027 - 2534
y 坐标误差: 0.0px（全部轮次）
匹配分数:   0.162 - 0.186
候选间隔:   0.032 - 0.061
```

目标是本地合成纹理，不代表这套参数可以直接用于真实站点的验证码图像。

这只是一套测试工具，不包含对真实站点验证码的识别、轨迹伪造或绕过逻辑。
